Unit I: Introduction to Data Structures and Algorithms

Q1. Define Abstract Data Type (ADT) and give the complete classification of Data Structures. Compare Linear and Non-Linear Data Structures with suitable examples. 7 Marks • Oct 2025 / PVG QB
SPPU Marking Split: ADT Definition & Operations (2M) · Classification Tree Diagram (2M) · Linear vs Non-Linear Table (2M) · Examples (1M)

1. Definition & Core Principle:

  • Data Structure: A systematic way of organizing, storing, and managing data items in memory together with the logical relationships among them so that operations (insertion, deletion, search, traversal) execute efficiently.
  • Abstract Data Type (ADT): A mathematical specification of a data type defined strictly by its domain of values and the set of legal operations (interface), completely hiding the underlying memory representation and implementation details (information hiding). For example, the Stack ADT specifies push(x), pop(), peek(), and isEmpty() regardless of whether an array or linked list is used internally.

2. Neat Labelled Diagram:

Diagram Explanation (How to Describe in Exam)
  • Primitive vs Non-Primitive: Primitive types (int, char, float, pointers) store single atomic values directly supported by the CPU; non-primitive structures combine multiple values into organized collections.
  • Linear Branch: Elements form a single sequence with unique predecessor/successor links — divided into Static (fixed-size Arrays) and Dynamic (Linked Lists, Stacks, Queues).
  • Non-Linear Branch: Elements are linked hierarchically (Trees) or as arbitrary multi-path networks (Graphs) without a single linear traversal order.

4. Key Takeaways & Real-World Applications:

  • ADT Advantage: Changing a PriorityQueue ADT implementation from an unsorted array to a Binary Heap upgrades insertion/extraction from $O(n)$ to $O(\log n)$ without modifying caller code.
  • Real-Time Uses: Linear structures power undo history (Stack) and printer spooling (Queue); non-linear structures power file systems (Trees) and GPS road networks (Graphs).
Q2. Compare Static and Dynamic Data Structures. Discuss Ephemeral and Persistent Data Structures with examples and significance. 6 Marks • Oct 2025 Q2a / Assign 01
SPPU Marking Split: Static vs Dynamic Table (2M) · Diagram (1.5M) · Ephemeral vs Persistent Explanation & Comparison (2.5M)

1. Definition & Core Principle:

  • Static Data Structure: A structure whose memory size and layout are fixed at compile time (or creation time) in contiguous memory (e.g., C static array int A[100]).
  • Dynamic Data Structure: A structure whose size grows or shrinks flexibly at runtime via heap allocation/deallocation (e.g., Linked List, Dynamic BST, Python list resizing).
  • Ephemeral vs Persistent Data Structure: An ephemeral structure modifies data in-place so every update destroys the previous version. A persistent structure preserves previous versions whenever updated (via path copying), enabling undo/time-travel queries.

2. Neat Labelled Diagram:

Diagram Explanation (How to Describe in Exam)
  • Left Panel: Static arrays occupy a contiguous fixed block allocated upfront (unused slots remain wasted), whereas Dynamic linked lists allocate individual heap nodes on demand connected via pointers.
  • Right Panel (Persistent DS): When updating node B to 99 in version V2, a new node 99 is created pointing to the existing unchanged tail C → D; V1 Head still accesses the original version B → C → D.

4. Significance in Modern Software Engineering:

  • Concurrency & Thread Safety: Persistent data structures are inherently immutable, allowing lock-free parallel reads across threads without race conditions.
  • Auditability & Rollback: Essential for version control (Git), collaborative text editors (CRDTs), and transactional databases (MVCC).
Q3. Explain Asymptotic Notations — Big-O ($O$), Omega ($\Omega$), and Theta ($\Theta$) — with formal mathematical definitions, examples, and order-of-growth curves. 6 Marks • Oct 2025 Q1a / Assign 01
SPPU Marking Split: Definitions & Inequalities (2M) · Order-of-Growth Curve Diagram (2M) · Numerical Proof Example (1M) · Complexity Hierarchy (1M)

1. Definition & Core Principle:

Asymptotic Notations express the limiting running time or space growth of an algorithm as input size $n \to \infty$, ignoring machine-dependent constant factors and lower-order terms:

  • Big-O ($O$, Asymptotic Upper Bound): $f(n) = O(g(n))$ iff $\exists\, c > 0$ and $n_0 \ge 1$ such that $0 \le f(n) \le c \cdot g(n)$ for all $n \ge n_0$. Represents the worst-case ceiling.
  • Big-Omega ($\Omega$, Asymptotic Lower Bound): $f(n) = \Omega(g(n))$ iff $\exists\, c > 0$ and $n_0 \ge 1$ such that $0 \le c \cdot g(n) \le f(n)$ for all $n \ge n_0$. Represents the best-case floor.
  • Big-Theta ($\Theta$, Asymptotic Tight Bound): $f(n) = \Theta(g(n))$ iff $\exists\, c_1, c_2 > 0$ and $n_0 \ge 1$ such that $0 \le c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$ (equivalently, $f(n) = O(g(n))$ AND $f(n) = \Omega(g(n))$).

2. Neat Labelled Diagram:

Diagram Explanation (How to Describe in Exam)
  • Threshold $n_0$: For all input sizes to the right of the vertical dashed line $n_0$, asymptotic dominance holds permanently regardless of fluctuations for small $n < n_0$.
  • Sandwich Property ($\Theta$): $f(n)$ lies strictly between $c_1 \cdot g(n)$ and $c_2 \cdot g(n)$ after $n_0$, proving exact growth rate equivalence.
  • Growth Curves: Exponential $2^n$ explodes vertically even for small $n$, whereas $O(\log n)$ and $O(1)$ stay nearly flat as $n \to \infty$.

3. Worked Proof Example ($f(n) = 3n^2 + 5n + 2$):

Proving $3n^2 + 5n + 2 = \Theta(n^2)$
  • Upper Bound ($O$): For all $n \ge 1$, $5n \le 5n^2$ and $2 \le 2n^2$. Thus $3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2$. Choosing $c_2 = 10, n_0 = 1 \implies f(n) = O(n^2)$.
  • Lower Bound ($\Omega$): For all $n \ge 1$, $3n^2 + 5n + 2 \ge 3n^2$. Choosing $c_1 = 3, n_0 = 1 \implies f(n) = \Omega(n^2)$.
  • Tight Bound ($\Theta$): Since $3n^2 \le f(n) \le 10n^2$ for all $n \ge 1$, we conclude $f(n) = \Theta(n^2)$.

4. Complexity Growth Hierarchy & Applications:

  • Standard Ordering: $O(1) < O(\log n) < O(\sqrt{n}) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$.
  • Practical Rule: For $n = 10^6$, an $O(n \log n)$ sort finishes in milliseconds ($\approx 2\times 10^7$ ops), whereas an $O(n^2)$ sort requires $\approx 10^{12}$ ops (hours).
Q4. Explain the Frequency / Step-Count Method. Apply it line-by-line to determine the time complexity of: (a) Nested triangular loop (PVG Q15) and (b) Python oddEven(n) (Oct 2025 Q2b). 8 Marks • Oct 2025 Q2b / PVG Q15
SPPU Marking Split: Step-Count Rules (1.5M) · Part (a) Trace Table & Sum (3.5M) · Part (b) Trace & Complexity Justification (3M)

1. Definition & Core Principle:

The Frequency / Step-Count Method measures an algorithm's execution cost in machine-independent program steps. For every executable statement $i$, we compute two quantities: Steps per Execution ($s/e$) and Frequency ($f_i$), summing $\text{Total Steps} = \sum (s/e)_i \times f_i$ to form a polynomial $T(n)$.

2. Neat Labelled Diagram (Triangular Iteration Grid for Part a):

Diagram Explanation (How to Describe in Exam)
  • Left (Triangular Loop): For each outer iteration $i \in [0, N-1]$, the inner loop executes $N - i$ times, forming a triangular sum $\sum_{i=0}^{N-1}(N-i) = \frac{N(N+1)}{2}$.
  • Right (Linear Loop): oddEven(n) executes a single sequential loop of $n-1$ iterations with $O(1)$ work per iteration.

1. Core Principle:

The asymptotic complexity of structured programs is determined by the nesting depth and loop step multiplier (additive updates $\to$ linear factors; multiplicative updates $\to$ logarithmic factors).

2. Neat Labelled Diagram (Halving & Doubling Iteration Trace):

Q6. Explain Divide & Conquer and Greedy algorithmic strategies with SPPU Case Studies (E-Commerce Product Sorting & Google Calendar Scheduling). Compare Divide & Conquer, Greedy, and Dynamic Programming. 6 Marks • PVG Q3, Q7 / Assign 01
SPPU Marking Split: Strategy Explanations & Case Studies (2.5M) · Workflow SVG (1.5M) · 3-Way Comparison Table (2M)

1. Definitions & SPPU Case Studies:

  • Divide & Conquer (D&C): Recursively breaks a problem into smaller independent subproblems (Divide), solves them recursively (Conquer), and merges their answers (Combine). Case Study — E-Commerce Product Sorting: Sorting 100,000 products by price/rating uses MergeSort or QuickSort ($\Theta(n \log n)$) to partition product lists cleanly into sorted halves.
  • Greedy Strategy: Builds a solution step-by-step by always picking the locally optimal feasible choice without backtracking. Case Study — Google Calendar Scheduling (Activity Selection): Given meeting intervals $[s_i, f_i]$, greedily sorting by earliest finish time $f_i$ and selecting each non-overlapping meeting schedules the maximum number of conflict-free meetings in $O(n \log n)$ time.
  • Dynamic Programming (DP): Solves problems with overlapping subproblems and optimal substructure by storing subproblem results in a table (memoization / tabulation) to avoid redundant recomputation.

2. Neat Labelled Diagram:

Diagram Explanation (How to Describe in Exam)
  • Left (D&C): Splits an input of size $n$ into independent subproblems of size $n/2$, solves them recursively, and merges sorted lists cleanly in $O(n \log n)$.
  • Right (Greedy): Meetings are sorted by end time; M1 [9-11] finishes first so it is picked, M2 overlaps so it is discarded immediately without backtracking, and M3 then M4 are selected.

4. Key Exam Takeaways:

  • Use Greedy for Fractional Knapsack and MST ($O(E \log V)$), but switch to Dynamic Programming for 0/1 Knapsack where greedy weight-to-value ratio fails to guarantee optimal profit.

Q1. Explain Array as an ADT and its memory storage representation. Derive Row-Major and Column-Major address formulas for 2D arrays, and find the address of P[10][20] in P[50][60] given Base = 6800 and element size $w = 2$ bytes. 6 Marks • CompSci Oct 2025 Q3a / Assign 02
SPPU Marking Split: Array ADT & Operations (1.5M) · Row vs Col Major SVG (1.5M) · Formula Derivation (1.5M) · Solved Numerical (1.5M)

1. Definition & Core Principle:

An Array ADT is a homogeneous, finite, ordered collection of fixed-size elements stored in contiguous memory locations, supporting $O(1)$ random access via index arithmetic. Key ADT operations: Create(size), Retrieve(i) ($O(1)$), Store(i, val) ($O(1)$), Insert(i, val) ($O(n)$), Delete(i) ($O(n)$), and Traverse() ($O(n)$).

2. Neat Labelled Diagram (2D Grid to 1D Linear Memory):

Diagram Explanation (How to Describe in Exam)
  • Row-Major Layout: Stores row 0 completely before row 1. Reaching row $i$ skips $(i - L_r)$ complete rows of length $C$, plus $(j - L_c)$ elements in the current row.
  • Column-Major Layout: Stores column 0 completely before column 1. Reaching column $j$ skips $(j - L_c)$ complete columns of height $R$, plus $(i - L_r)$ elements down the column.

3. General Address Formulas & Solved Numerical (CompSci Oct 2025 Q3a):

Generalized Formulas for $A[L_r..U_r][L_c..U_c]$ where $R = U_r - L_r + 1,\; C = U_c - L_c + 1$
  • Row-Major Address: $\text{Loc}(A[i][j]) = \text{Base} + w \cdot \big[(i - L_r) \cdot C + (j - L_c)\big]$
  • Column-Major Address: $\text{Loc}(A[i][j]) = \text{Base} + w \cdot \big[(j - L_c) \cdot R + (i - L_r)\big]$

Given Data: Array P[50][60] $\implies R = 50, C = 60$, Base $B = 6800$, element size $w = 2$ bytes, 0-based indexing ($L_r = 0, L_c = 0$), target element P[10][20] ($i = 10, j = 20$):

  1. Row-Major Address: $$\text{Loc}(P[10][20]) = 6800 + 2 \cdot [(10 - 0)\cdot 60 + (20 - 0)] = 6800 + 2 \cdot [600 + 20] = 6800 + 1240 = \mathbf{8040}$$
  2. Column-Major Address: $$\text{Loc}(P[10][20]) = 6800 + 2 \cdot [(20 - 0)\cdot 50 + (10 - 0)] = 6800 + 2 \cdot [1000 + 10] = 6800 + 2020 = \mathbf{8820}$$

4. Key Takeaways & Cache Locality:

  • Row-major traversal (for i: for j: A[i][j]) in C/Python achieves spatial cache locality and runs dramatically faster than column-major traversal on large matrices.
Q2. What is a Sparse Matrix? Explain its 3-Tuple (Triplet) representation. Write the Fast Transpose algorithm, trace rowTerms[] and startingPos[] on a $4 \times 5$ sparse matrix, and compare Simple vs Fast Transpose. 8 Marks • Assign 02 Q5, Q6, Q7
SPPU Marking Split: Definition & Triplet Format (1.5M) · Trace SVG (2M) · Fast Transpose Algorithm & Dry Run (3M) · Complexity Comparison (1.5M)

1. Definition & Core Principle:

A Sparse Matrix is a 2D matrix in which the vast majority of elements are zero (typically non-zero count $t \ll R \times C$). Storing all zeroes wastes $O(R \cdot C)$ space, so we store only non-zero entries in a 3-Tuple (Triplet) Table of size $(t+1) \times 3$: row 0 stores metadata (rows, cols, numTerms), and rows 1..t store (row, col, value) sorted in row-major order.

2. Neat Labelled Diagram (Fast Transpose Array Trace):

Diagram Explanation (How to Describe in Exam)
  • rowTerms[c]: One linear pass over $A[1..6]$ counts how many non-zero terms sit in each column $c \in [0..4]$, yielding $[0, 1, 3, 1, 1]$.
  • startingPos[c]: Prefix sum computes the exact starting slot in $B$ for each transposed row $c$, yielding $[1, 1, 2, 5, 6]$.
  • Direct Placement: A single pass over $A[1..6]$ places $A[1]=(0,2,3)$ at $B[\text{startingPos}[2]] = B[2]$ and increments $\text{startingPos}[2] \to 3$, placing all 6 entries directly in sorted order.

3. Fast Transpose Python Implementation & Complexity Comparison:

def fast_transpose(A):
    rows, cols, terms = A[0]
    B = [[0, 0, 0] for _ in range(terms + 1)]
    B[0] = [cols, rows, terms]
    if terms == 0:
        return B

    row_terms = [0] * cols
    for i in range(1, terms + 1):
        row_terms[A[i][1]] += 1              # Frequency of each column

    starting_pos = [0] * cols
    starting_pos[0] = 1
    for c in range(1, cols):
        starting_pos[c] = starting_pos[c - 1] + row_terms[c - 1]

    for i in range(1, terms + 1):
        c = A[i][1]
        pos = starting_pos[c]
        B[pos] = [A[i][1], A[i][0], A[i][2]] # Swap row <-> col
        starting_pos[c] += 1
    return B

Q3. Explain Linear Search, Binary Search, and Fibonacci Search. Trace Binary Search on [9, 17, 23, 38, 45, 50, 57, 76, 90, 100] for keys 23 and 90 (Oct 2025 Q3b), and compare all three searching methods. 7 Marks • Oct 2025 Q3b / PVG Q1, Q3
SPPU Marking Split: Precursor & Logic (1.5M) · Binary/Fibonacci Split SVG (1.5M) · Worked Traces (2M) · 3-Way Comparison Table (2M)

1. Definition & Precursor Requirements:

  • Linear (Sequential) Search: Scans elements sequentially from index $0$ to $n-1$. Requires no sorting; works on arrays and linked lists.
  • Binary Search: Divide & Conquer search that compares key against A[mid] and discards half the search space each step. Precursor Requirement: Array must be sorted and support $O(1)$ random access.
  • Fibonacci Search: Sorted-array search dividing range $[0..n-1]$ into unequal segments of Fibonacci lengths ($F_{k-2}$ and $F_{k-1}$) using only addition and subtraction (avoiding CPU division/bit-shifts).

def partition(arr, low, high):
    pivot = arr[low]
    i, j = low + 1, high
    while True:
        while i <= j and arr[i] <= pivot:
            i += 1
        while i <= j and arr[j] >= pivot:
            j -= 1
        if i <= j:
            arr[i], arr[j] = arr[j], arr[i]
        else:
            break
    arr[low], arr[j] = arr[j], arr[low]
    return j

def quick_sort(arr, low, high):
    if low < high:
        p = partition(arr, low, high)
        quick_sort(arr, low, p - 1)
        quick_sort(arr, p + 1, high)

def merge(left, right):
    res, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:           # '<=' preserves stability!
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    return res + left[i:] + right[j:]

def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    return merge(merge_sort(arr[:mid]), merge_sort(arr[mid:]))

1. Definition & Core Principle:

A Stack is a linear Abstract Data Type operating under the LIFO (Last-In, First-Out) discipline, where insertions (push) and deletions (pop) occur strictly at one end called top. Attempting push when full causes Stack Overflow; attempting pop/peek when empty causes Stack Underflow.

class TwoStacks:
    def __init__(self, cap=10):
        self.cap = cap
        self.arr = [None] * cap
        self.top1 = -1
        self.top2 = cap

    def push1(self, x):
        if self.top1 + 1 == self.top2:
            raise OverflowError("Stack Overflow: Array Full")
        self.top1 += 1
        self.arr[self.top1] = x

    def push2(self, x):
        if self.top1 + 1 == self.top2:
            raise OverflowError("Stack Overflow: Array Full")
        self.top2 -= 1
        self.arr[self.top2] = x

    def pop1(self):
        if self.top1 == -1:
            raise IndexError("Stack 1 Underflow")
        val = self.arr[self.top1]; self.top1 -= 1; return val

    def pop2(self):
        if self.top2 == self.cap:
            raise IndexError("Stack 2 Underflow")
        val = self.arr[self.top2]; self.top2 += 1; return val

Q1. Define Hashing terminology (Bucket, Collision, Probe, Synonym, Overflow, Perfect Hash Function, Load Factor). State the properties of a good hash function and explain four hash functions with numerical examples. 6 Marks • Oct 2025 Q7a / Assign 04 Q1, Q2
SPPU Marking Split: Key Terms & Load Factor (2M) · 5 Properties (1.5M) · 4 Hash Functions with Examples (2.5M)

1. Core Definitions & Terminology:

  • Hashing & Hash Table: A technique mapping a large key universe $U$ via a mathematical Hash Function $h(k)$ into indices $[0..m-1]$ of a fixed-size array (Hash Table) for $O(1)$ average search/insert/delete.
  • Bucket & Slot: A hash table partition holding $s \ge 1$ records; each individual record position is a slot.
  • Collision & Synonym: When two distinct keys $k_1 \ne k_2$ map to the same home address ($h(k_1) = h(k_2)$), a collision occurs; $k_1$ and $k_2$ are called synonyms.
  • Probe & Overflow: Each table slot inspection during search/insert is a probe. Overflow occurs when a key hashes to an already full bucket.
  • Perfect Hash Function: A one-to-one hash mapping over a static key set with zero collisions.
  • Load Factor ($\alpha$) & Load Density: Ratio of stored items $n$ to total table capacity: $\alpha = \frac{n}{m \cdot s}$ (for $s=1$ slot/bucket, $\alpha = \frac{n}{m}$). Load density measures active slot utilization.

2. Properties of a Good Hash Function:

  4. Low Collision Rate: Uses all bits/digits of the key (avalanche sensitivity).
  5. Table-Size Awareness: Works cleanly with prime table sizes $m$.

1. Definition & Core Principle:

  • Rehashing: The process of allocating a new, larger hash table (typically the smallest prime $\ge 2m$) and recomputing key % new_size to re-insert every active key whenever the load factor $\alpha = n / m$ crosses a threshold (commonly $\alpha ≥ 0.70$).

class HashDictionary:
    def __init__(self, cap=7):
        self.cap = cap
        self.count = 0
        self.buckets = [[] for _ in range(cap)]

    def _hash(self, word):                      # Polynomial rolling hash
        h = 0
        for ch in word.lower():
            h = (h * 31 + ord(ch)) % self.cap
        return h

    def insert(self, word, meaning):
        if (self.count + 1) / self.cap > 0.7:
            self._rehash()
        idx = self._hash(word)
        for pair in self.buckets[idx]:
            if pair[0] == word:
                pair[1] = meaning; return
        self.buckets[idx].append([word, meaning])
        self.count += 1

    def lookup(self, word):
        for k, v in self.buckets[self._hash(word)]:
            if k == word: return v
        return None

    def _rehash(self):
        old_buckets = self.buckets
        self.cap = self.cap * 2 + 1             # Resize to larger odd/prime cap
        self.buckets = [[] for _ in range(self.cap)]
        self.count = 0
        for chain in old_buckets:
            for k, v in chain: self.insert(k, v)

def bst_delete(root, key):
    if root is None:
        return None
    if key < root.key:
        root.left = bst_delete(root.left, key)
    elif key > root.key:
        root.right = bst_delete(root.right, key)
    else:
        if root.left is None: return root.right   # Case 1 & Case 2 (no left)
        if root.right is None: return root.left   # Case 2 (no right)
        succ = root.right                         # Case 3: Inorder Successor
        while succ.left:
            succ = succ.left
        root.key = succ.key
        root.right = bst_delete(root.right, succ.key)
    return root

1. Definition & Prefix-Free Property:

  • Huffman Coding: A lossless greedy compression algorithm that builds an optimal variable-length binary code tree based on symbol frequencies — assigning shorter bitstrings to frequent characters and longer bitstrings to rare characters.
  • Prefix-Free Property: Because all encoded symbols sit strictly at leaf nodes, no character's codeword is a prefix of any other codeword, allowing unambiguous streaming decoding without delimiter bits!
