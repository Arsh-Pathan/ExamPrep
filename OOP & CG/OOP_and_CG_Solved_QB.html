Q1. What is a programming paradigm? Differentiate between Procedural (POP) and Object-Oriented Programming (OOP), briefly explain Functional and Logic paradigms, and state why OOP is needed. 6 Marks • SPPU QB / Oct 2025
SPPU Marking Split: Definition & 4 Paradigms (1.5M) · Neat POP vs OOP Diagram (1.5M) · POP vs OOP Comparison Table (2M) · Need for OOP (1M)

1. Definition & Four Main Programming Paradigms

A programming paradigm is a fundamental style or computational model for structuring and organizing programs, defining how data and logic interact to solve problems.

  • Procedural Paradigm (POP): Organizes code as a sequence of step-by-step functions/procedures operating on shared global data (e.g., C, Pascal, Fortran).
  • Object-Oriented Paradigm (OOP): Models software as interacting objects that bundle private data and methods into single encapsulated units (e.g., Java, C++, Python).
  • Functional Paradigm: Treats computation as evaluation of pure mathematical functions, avoiding mutable state and side effects (e.g., Haskell, Lisp, Scala).
  • Logic / Rule-Based Paradigm: Uses formal logic facts and rules; the programmer declares what is true and an inference engine deduces answers (e.g., Prolog, Datalog).

2. Neat Labelled Diagram

Diagram Explanation (How to Describe in Exam)
  • Left (POP): Any procedure (funcA, funcB, funcC) can freely read or overwrite the shared global data pool, creating fragile dependencies in large programs.
  • Right (OOP): Each object wraps its own private data inside public methods; Object A interacts with Object B solely by sending a message (calling a public method).

4. Need for OOP & Key Takeaways

  • Managing Complexity: Large applications (banking, OS, CAD) become unmaintainable in POP because changing a global structure breaks dozens of functions.
  • Real-World Mapping: OOP directly models real-world entities (Student, Account, Shape), improving modularity, maintainability, and team scalability.

1. Core Principle

Object-Oriented Programming (OOP) is a methodology that designs software around classes (blueprints) and objects (runtime instances) governed by four foundational pillars: Encapsulation, Abstraction, Inheritance, and Polymorphism.

1. Definitions: JVM, JRE, and JDK

  • JVM (Java Virtual Machine): An abstract computing machine that loads, verifies, and executes Java Bytecode (.class), converting it into host-OS machine instructions.
  • JRE (Java Runtime Environment): Runtime package containing the JVM + Core Java Class Libraries (rt.jar / modules) required to run Java programs.
  • JDK (Java Development Kit): Complete software development bundle containing JRE + Development Tools (javac compiler, javadoc, jdb debugger) needed to write and compile Java code.

2. Neat Labelled Diagram

Diagram Explanation (How to Describe in Exam)
  • Compilation Stage: javac translates human-readable App.java into intermediate, platform-neutral App.class Bytecode rather than OS-specific binary code.
  • ClassLoader & Verifier: Loads .class bytes into memory, verifies bytecode safety (preventing illegal memory access), and initializes static fields.
  • Execution Engine: Combines the Interpreter (fast startup) and the JIT (Just-In-Time) Compiler (compiles frequently executed methods to native CPU instructions for high speed), while GC reclaims unused Heap objects.

  • Why WORA Works: Java Bytecode is identical everywhere, while the JVM itself is OS-specific (Windows JVM, Linux JVM, macOS JVM) and acts as a universal translator at runtime.

Q5. Explain Java Control Statements (if-else, switch, for, while, do-while, for-each, break, continue) with syntax and a Java program. 6 Marks • SPPU Oct 2025 / QB
SPPU Marking Split: Classification (1M) · Control Flow Diagram SVG + Explanation (1.5M) · Loop & Jump Comparison Table (1.5M) · Complete Java Program + Output (2M)

1. Definition & Classification

Control statements govern the order in which instructions execute in a Java program. They are grouped into Selection (if, if-else, switch), Iteration (while, do-while, for, for-each), and Jump (break, continue, return) statements.

2. Neat Labelled Diagram

Diagram Explanation (How to Describe in Exam)
  • while / for vs do-while: while tests the condition before entering the body (runs 0 times if initially false), whereas do-while executes the body first and tests at exit (minimum 1 run).
  • break vs continue: break immediately terminates the enclosing loop or switch, whereas continue skips remaining statements of only the current iteration.

3. Complete Java Program Demonstrating All Control Statements

public class ControlStatementsDemo {
    public static void main(String[] args) {
        int marks = 82, day = 2;

        // 1. if-else ladder
        if (marks >= 75) System.out.println("Result: Distinction");
        else if (marks >= 40) System.out.println("Result: Pass");
        else System.out.println("Result: Fail");

        // 2. switch statement
        switch (day) {
            case 1: System.out.println("Day: Monday"); break;
            case 2: System.out.println("Day: Tuesday"); break;
            default: System.out.println("Day: Other");
        }

        // 3. for loop with continue and break
        System.out.print("Odd numbers (<=7): ");
        for (int i = 1; i <= 10; i++) {
            if (i % 2 == 0) continue; // skip even numbers
            if (i > 7) break;         // stop loop after 7
            System.out.print(i + " ");
        }
        System.out.println();

        // 4. while & do-while loops
        int c = 3;
        while (c > 0) {
            System.out.print("W" + c + " ");
            c--;
        }
        int x = 10;
        do {
            System.out.println("\nDo-while ran once even though x >= 5: x=" + x);
        } while (x < 5);

        // 5. for-each (enhanced for) loop
        int[] scores = {70, 85, 90};
        int sum = 0;
        for (int s : scores) sum += s;
        System.out.println("Sum via for-each: " + sum);
    }
}
Output: Result: Distinction Day: Tuesday Odd numbers (<=7): 1 3 5 7 W3 W2 W1 Do-while ran once even though x >= 5: x=10 Sum via for-each: 245

4. Key Takeaways

  • Always end each switch case with break to prevent unintended fall-through execution.
  • Use for-each for read-only traversal of arrays and collections without index-out-of-bounds risk.

1. Five-Section Structure of a Java Program

Every well-formed Java source file follows five standard sections from top to bottom:

  1. Documentation Section: Single-line (//), multi-line (/* ... */), or Javadoc comments (/** ... */) stating program purpose and author.
  2. Package Statement (Optional): First executable line declaring the namespace (e.g., package com.sppu.lab1;).
  3. Import Statements (Optional): Loads predefined classes from Java Class Libraries (e.g., import java.util.Scanner;).
  4. Class / Interface Definitions: Encapsulates fields, constructors, and helper methods.
  5. Main Method Class: Contains public static void main(String[] args), the mandatory entry point invoked by the JVM.

2. Annotated Program & Java Class Libraries

/** 1. Documentation Section: Circle Area Program */
package geometry;                 // 2. Package Statement
import java.util.Scanner;         // 3. Import from Java Class Library

class CircleHelper {              // 4. Class Definition
    static double calcArea(double r) { return Math.PI * r * r; }
}

public class MainApp {            // 5. Main Method Class
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        double r = 5.0;           // Example radius
        System.out.println("Area = " + CircleHelper.calcArea(r));
        sc.close();
    }
}

  • The import statement resolves short class names (e.g., Scanner instead of java.util.Scanner) at compile time without embedding library bytecode into your source file.

Q1. Define Class and Object in Java. Explain field/method declaration, object creation using new, reference variables, and write a Java program for a Student class. 6 Marks • SPPU Oct 2025 / QB
SPPU Marking Split: Definitions (1M) · Stack vs Heap Memory Model SVG + Explanation (2M) · Field/Method & Reference Rules (1M) · Student Class Java Program (2M)

1. Formal Definitions

A class is a user-defined blueprint or template that groups fields (instance variables storing state) and methods (functions defining behavior). An object is a concrete runtime instance of a class dynamically allocated in Heap memory using the new operator.

2. Neat Labelled Diagram: Class & Object Memory Model (Stack vs Heap)

Diagram Explanation (How to Describe in Exam)
  • Object Creation (new): Student s1 = new Student(); allocates field memory (rollNo, name) on the Heap and returns its address (@0x100A) to reference variable s1 on the Stack.
  • Reference Aliasing: Assigning Student s2 = s1; copies only the address, not the object; modifying s2.rollNo also reflects through s1.
  • Method Area: Stores one shared copy of Student method bytecode (display()) referenced by every instance.

3. Java Program: Student Class with Fields, Methods & Reference Variables

class Student {
    // Field declarations (instance variables)
    int rollNo;
    String name;

    // Method definitions
    void setDetails(int r, String n) {
        rollNo = r;
        name = n;
    }

    void display() {
        System.out.println("Roll No: " + rollNo + " | Name: " + name);
    }
}

public class StudentDemo {
    public static void main(String[] args) {
        Student s1 = new Student();       // Instantiate object on Heap
        s1.setDetails(101, "Aarav");      // Access member via dot (.) operator
        s1.display();

        Student s2 = s1;                  // Reference variable aliasing
        s2.name = "Aarav Patil";          // Updates the same Heap object
        s1.display();
    }
}
Output: Roll No: 101 | Name: Aarav Roll No: 101 | Name: Aarav Patil

4. Key Takeaways

  • Declaring Student s1; alone only creates a null reference on the stack; calling a method before new Student() throws NullPointerException.
Q2. What is a Constructor? Explain Default, Parameterized, and Constructor Overloading along with the this keyword, getters/setters, and static members with a Java program. 7 Marks • SPPU Oct 2025 / QB
SPPU Marking Split: Definitions & Rules (1.5M) · this & static Memory SVG + Explanation (1.5M) · Complete Java Program (3M) · Takeaways (1M)

1. Definitions & Constructor Types

A constructor is a special block of code having the exact same name as the class and no return type (not even void), invoked automatically when new creates an object to initialize its fields.

  • Default Constructor: Accepts zero parameters. Java supplies an implicit default constructor only if no explicit constructor is defined.
  • Parameterized Constructor: Accepts arguments to initialize instance variables with custom values at creation time.
  • Constructor Overloading: Defining two or more constructors in the same class with different parameter counts or types for flexible initialization.
  • this Keyword: Holds a reference to the current invoking object; resolves field shadowing (this.title = title;) and invokes another constructor via this(...) as the first statement.
  • static Members: Belong to the class rather than individual objects; shared across all instances (e.g., an object counter) and accessed via ClassName.member.

2. Neat Labelled Diagram: this Reference & Shared static Memory

Diagram Explanation (How to Describe in Exam)
  • Instance vs Static: Each object (b1, b2) gets its own separate copy of title and price on the Heap, whereas static int count resides once in the Method Area and increments for every constructor call.
  • Role of this: Inside b1's constructor/setter, this points to b1; inside b2, this points to b2.

3. Java Program: Constructor Overloading, this, Getters/Setters & static

class Book {
    private String title;
    private double price;
    private static int bookCount = 0; // Shared static counter

    // 1. Default constructor chaining via this(...)
    Book() {
        this("Untitled", 200.0);
    }

    // 2. Single-arg overloaded constructor
    Book(String title) {
        this(title, 350.0);
    }

    // 3. Full parameterized constructor
    Book(String title, double price) {
        this.title = title; // 'this' resolves shadowing
        setPrice(price);    // Reuse validation in setter
        bookCount++;
    }

    // Getter (Accessor) & Setter (Mutator)
    public String getTitle() { return title; }
    public void setPrice(double price) {
        if (price > 0) this.price = price;
    }

    public static int getBookCount() { return bookCount; }

    public void show() {
        System.out.println(title + " : Rs. " + price);
    }
}

public class ConstructorDemo {
    public static void main(String[] args) {
        Book b1 = new Book();
        Book b2 = new Book("Java Core", 520.0);
        b1.show();
        b2.show();
        System.out.println("Total Books Created = " + Book.getBookCount());
    }
}
Output: Untitled : Rs. 200.0 Java Core : Rs. 520.0 Total Books Created = 2

4. Key Takeaways

  • A static method cannot directly access non-static fields or use this because it belongs to the class, not any specific instance.
  • Get/Set methods preserve encapsulation by allowing range validation (e.g., rejecting negative prices) before mutating private state.
Q3. Differentiate between Method Overloading and Method Overriding. Write a Java program to overload area(), and explain how primitive and object arguments are passed and returned. 6 Marks • SPPU Oct 2025 / QB

1. Definitions

Method Overloading defines multiple methods in the same class sharing the same name but differing in parameter list (count, type, or order), resolved at compile time. Method Overriding redefines a superclass method in a subclass with the exact same signature, resolved at runtime.

2. Neat Labelled Diagram: Argument Passing (Call-by-Value in Java)

Diagram Explanation (How to Describe in Exam)
  • Primitives: Passing an int sends a numeric copy; mutating the parameter leaves the caller's variable untouched.
  • Objects: Passing an object sends a copy of its Heap address (@20B), so mutating p.side updates the caller's Heap object, while reassigning p = new Box() does not rebind the caller's variable.

4. Java Program: Overloading area() & Returning an Object

class ShapeCalc {
    double side;
    ShapeCalc(double side) { this.side = side; }

    // Overloaded methods for Square and Rectangle area
    double area(double s) { return s * s; }
    double area(double l, double b) { return l * b; }

    // Passing object as parameter & returning a new object
    ShapeCalc scaleBy(ShapeCalc other, double factor) {
        return new ShapeCalc((this.side + other.side) * factor);
    }
}

public class OverloadDemo {
    public static void main(String[] args) {
        ShapeCalc s1 = new ShapeCalc(4);
        ShapeCalc s2 = new ShapeCalc(6);
        System.out.println("Square Area (side=5): " + s1.area(5));
        System.out.println("Rectangle Area (4x7): " + s1.area(4, 7));
        ShapeCalc s3 = s1.scaleBy(s2, 0.5);
        System.out.println("Returned Object Side: " + s3.side);
    }
}

Q4. Explain 1D, 2D, and Jagged Arrays in Java, Variable-Length Arguments (Varargs), and Command-Line Arguments with a complete Java program. 6 Marks • SPPU Oct 2025 / QB
SPPU Marking Split: Array Declaration & Rules (1M) · 2D Jagged Array Memory SVG + Explanation (1.5M) · Varargs & CLI Arguments (1.5M) · Complete Java Program (2M)

1. Definitions

An array in Java is a fixed-size, zero-indexed Heap object holding homogeneous elements with a built-in .length property. A 2D jagged array is an array of arrays where inner rows can have varying lengths. Varargs (type... param) accept zero or more arguments as an implicit array.

2. Neat Labelled Diagram: 2D Jagged Array Memory Layout

Diagram Explanation (How to Describe in Exam)
  • Array of References: Unlike C's contiguous 2D matrix block, Java stores an outer 1D array of row references (jag[0], jag[1], jag[2]), each pointing to a separate Heap 1D array of arbitrary length.
  • Varargs & CLI Rules: A method can have at most one varargs parameter and it must be the last parameter (void log(String tag, int... nums)). Command-line arguments passed after java App a1 a2 arrive as args[0], args[1].

3. Java Program: 1D Array Passing, 2D Jagged Array, Varargs & CLI

public class ArrayVarargsDemo {
    static int sum1D(int[] arr) {
        int s = 0;
        for (int v : arr) s += v;
        return s;
    }

    static double avgVarargs(double... nums) {
        if (nums.length == 0) return 0;
        double total = 0;
        for (double n : nums) total += n;
        return total / nums.length;
    }

    public static void main(String[] args) {
        int[] marks = {75, 85, 90};
        System.out.println("1D Array Sum: " + sum1D(marks));

        // 2D Jagged Array
        int[][] jag = { {1, 2}, {3, 4, 5, 6}, {7, 8, 9} };
        System.out.println("Jagged row lengths: " + jag[0].length + ", " + jag[1].length);

        // Varargs calls
        System.out.println("Avg (3 args): " + avgVarargs(10, 20, 30));
        System.out.println("Avg (5 args): " + avgVarargs(5, 10, 15, 20, 25));

        // Command-line arguments check
        System.out.println("CLI args count: " + args.length);
    }
}
Output (run with: java ArrayVarargsDemo): 1D Array Sum: 250 Jagged row lengths: 2, 4 Avg (3 args): 20.0 Avg (5 args): 15.0 CLI args count: 0

4. Key Takeaways

1. Mathematical Derivation ($0 \le m \le 1$)

Bresenham's Line Algorithm rasterizes lines using pure integer arithmetic (no floating-point division or rounding). Given current pixel $(x_k, y_k)$ along $y = m(x_k + 1) + c$, the next candidate pixels are $E = (x_k + 1, y_k)$ and $NE = (x_k + 1, y_k + 1)$.

Let vertical distances from the ideal line $y = \frac{\Delta y}{\Delta x}(x_k + 1) + c$ to $y_k$ and $y_k + 1$ be:

$$d_1 = y - y_k = \frac{\Delta y}{\Delta x}(x_k + 1) + c - y_k, \qquad d_2 = (y_k + 1) - y = y_k + 1 - \frac{\Delta y}{\Delta x}(x_k + 1) - c$$

Subtracting $d_2$ from $d_1$ and multiplying by $\Delta x > 0$ defines the integer decision parameter $p_k$:

$$p_k = \Delta x (d_1 - d_2) = 2\Delta y \cdot x_k - 2\Delta x \cdot y_k + C, \quad \text{where } C = 2\Delta y + \Delta x(2c - 1)$$
  • If $p_k < 0$ ($d_1 < d_2$), choose lower pixel $(x_k + 1, y_k)$, so $y_{k+1} = y_k$: $$p_{k+1} = p_k + 2\Delta y(x_{k+1}-x_k) - 2\Delta x(y_{k+1}-y_k) = p_k + 2\Delta y$$
  • If $p_k \ge 0$ ($d_1 \ge d_2$), choose upper pixel $(x_k + 1, y_k + 1)$, so $y_{k+1} = y_k + 1$: $$p_{k+1} = p_k + 2\Delta y - 2\Delta x$$
  • Substituting $(x_0, y_0)$ and $c = y_0 - \frac{\Delta y}{\Delta x}x_0$ gives initial parameter: $\mathbf{p_0 = 2\Delta y - \Delta x}$.

1. Windowing, Clipping & Cohen-Sutherland 4-Bit Outcodes

Windowing selects a world-coordinate rectangle (the Window) for display inside a device-coordinate rectangle (the Viewport). Clipping removes parts of primitives lying outside the window.

Cohen-Sutherland Algorithm partitions 2D space into 9 regions using a 4-bit region code (TBRL: Top, Bottom, Right, Left):

  • Bit 4 (MSB, Top): $y > y_{\max}$ • Bit 3 (Bottom): $y < y_{\min}$ • Bit 2 (Right): $x > x_{\max}$ • Bit 1 (LSB, Left): $x < x_{\min}$.
  • Trivial Accept: $\text{code}(P_1) = 0000$ AND $\text{code}(P_2) = 0000$. Trivial Reject: $(\text{code}(P_1) \ \& \ \text{code}(P_2)) \neq 0000$.

Diagram Explanation (How to Describe in Exam)

  • Sutherland-Hodgman: Feeds the polygon vertex list sequentially through 4 clippers (Left, Right, Bottom, Top), applying the 4 edge-transition rules per edge $(V_1 \to V_2)$.

3. Worked Numerical Trace: Cohen-Sutherland Line Clipping

Given window $(x_{\min}, y_{\min}) = (10, 10)$ to $(x_{\max}, y_{\max}) = (50, 40)$ and line $P_1(5, 20)$ to $P_2(35, 50)$:

  1. Assign Outcodes: $P_1(5, 20)$ has $x < 10 \implies \text{code}(P_1) = \mathbf{0001}$ (Left). $P_2(35, 50)$ has $y > 40 \implies \text{code}(P_2) = \mathbf{1000}$ (Top).
  2. Bitwise Checks: $\text{code}(P_1) \ | \ \text{code}(P_2) \neq 0000$ (not trivially accepted); $\text{code}(P_1) \ \& \ \text{code}(P_2) = 0001 \ \& \ 1000 = 0000$ (not trivially rejected → must clip).
  3. Slope: $m = \frac{50 - 20}{35 - 5} = \frac{30}{30} = 1$.
  4. Clip $P_1$ against Left edge ($x = 10$): $y = 20 + 1(10 - 5) = 25 \implies \mathbf{P_1'(10, 25)}$ with outcode $\mathbf{0000}$.
  5. Clip $P_2$ against Top edge ($y = 40$): $x = 35 + \frac{40 - 50}{1} = 25 \implies \mathbf{P_2'(25, 40)}$ with outcode $\mathbf{0000}$.
  6. Final Decision: Both outcodes are 0000 → Accept clipped segment $(10, 25)$ to $(25, 40)$.

4. Key Takeaways

  • Cohen-Sutherland works only on rectangular windows; Sutherland-Hodgman works for any convex clipping polygon, though concave output polygons may leave degenerate connecting edges along the border.

1. Homogeneous Coordinates & 2D Basic Matrices

Homogeneous coordinates represent a 2D point $(x, y)$ as a 3-element column vector $(x, y, 1)^T$ (or $(X, Y, W)^T$ where $x = X/W, y = Y/W$) so that additive translation and multiplicative scaling/rotation all become uniform $3 \times 3$ matrix multiplications ($P' = M \cdot P$).

$$T(t_x, t_y) = \begin{bmatrix} 1 & 0 & t_x \\ 0 & 1 & t_y \\ 0 & 0 & 1 \end{bmatrix}, \quad S(s_x, s_y) = \begin{bmatrix} s_x & 0 & 0 \\ 0 & s_y & 0 \\ 0 & 0 & 1 \end{bmatrix}, \quad R(\theta) = \begin{bmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{bmatrix}$$

Rotation About Arbitrary Pivot $(x_f, y_f)$: Compose 3 steps: (1) Translate pivot to origin $T(-x_f, -y_f)$, (2) Rotate by $\theta$ around origin $R(\theta)$, (3) Translate back $T(x_f, y_f)$:

$$M = T(x_f, y_f) \cdot R(\theta) \cdot T(-x_f, -y_f) = \begin{bmatrix} \cos\theta & -\sin\theta & x_f(1-\cos\theta)+y_f\sin\theta \\ \sin\theta & \cos\theta & y_f(1-\cos\theta)-x_f\sin\theta \\ 0 & 0 & 1 \end{bmatrix}$$

Diagram Explanation (How to Describe in Exam)

  • Right-to-Left Order: In column-vector form $P' = M \cdot P$, the transformation applied first appears on the rightmost side of the matrix product.

1. Parametric Bezier Equation & Bernstein Properties

A Bezier curve of degree $n$ defined by $n+1$ control points $P_0, \dots, P_n$ for parameter $t \in [0, 1]$ is:

$$P(t) = \sum_{i=0}^{n} P_i \cdot B_{i,n}(t), \quad B_{i,n}(t) = \binom{n}{i} t^i (1-t)^{n-i}$$

For a Cubic Bezier Curve ($n = 3$, 4 control points $P_0, P_1, P_2, P_3$):

$$P(t) = (1-t)^3 P_0 + 3t(1-t)^2 P_1 + 3t^2(1-t) P_2 + t^3 P_3$$
  • Partition of Unity: $\sum B_{i,n}(t) = 1$ and $B_{i,n}(t) \ge 0 \implies$ curve stays strictly inside the Convex Hull of control points.
  • Endpoint Interpolation & Tangency: Passes through $P(0) = P_0$ and $P(1) = P_3$; initial/final tangents follow $P_1 - P_0$ and $P_3 - P_2$.

2. Window-to-Viewport Mapping Formula & Numerical

Maps a world point $(x_w, y_w)$ inside window $(x_{w\min}, y_{w\min}) \text{ to } (x_{w\max}, y_{w\max})$ onto viewport $(x_{v\min}, y_{v\min}) \text{ to } (x_{v\max}, y_{v\max})$:

$$x_v = x_{v\min} + (x_w - x_{w\min})\frac{x_{v\max} - x_{v\min}}{x_{w\max} - x_{w\min}}, \quad y_v = y_{v\min} + (y_w - y_{w\min})\frac{y_{v\max} - y_{v\min}}{y_{w\max} - y_{w\min}}$$

Example: Map $(50, 60)$ from window $(0,0)\text{--}(100,100)$ to viewport $(20,40)\text{--}(220,140)$: $s_x = \frac{200}{100} = 2, \; s_y = \frac{100}{100} = 1 \implies x_v = 20 + 50(2) = \mathbf{120}, \; y_v = 40 + 60(1) = \mathbf{100} \implies \mathbf{(120, 100)}$.

3. Non-Commutativity Proof ($T \cdot R \neq R \cdot T$)

Take point $P(2, 1)$, Translation $T(3, 2)$, and CCW Rotation $R(90^\circ)$:

  • Case 1 (Rotate first, then Translate: $T \cdot R \cdot P$): $R(90^\circ)(2,1) = (-1, 2)$; then $+ (3, 2) = \mathbf{(2, 4)}$.
  • Case 2 (Translate first, then Rotate: $R \cdot T \cdot P$): $T(3, 2)(2, 1) = (5, 3)$; then $R(90^\circ)(5, 3) = \mathbf{(-3, 5)}$.

Since $(2, 4) \neq (-3, 5)$, matrix order critically alters the final transformed position.
